# 日报窗口锚点改 20:00、推送默认取昨天 — 实现方案

日期：2026-08-31（撰写）／2026-09-01（执行）
执行前提：**2026-09-01 早上 11:00 前的那次推送已完成**，详见文末「切换时序」。

## 一句话

把日报窗口锚点从 11:00 改到 20:00，并让推送在不带 `--date` 时默认取
**昨天**的窗口。改完后：每天 18:00 下班前抓取，次日全天任意时刻推送，
内容恒为「前天 20:00 → 昨天 20:00」这一段已截止的区间。

## 为什么改

现在锚点 11:00，硬约束是「抓取必须在 11:00 前跑完」，意味着要么早起、
要么让机器整夜开着等 07:00 的定时任务。改成 20:00 后，下班前跑抓取即可，
次日推送时窗口早已关闭，推送时刻完全自由。

## 目标行为

锚点 `DAILY_ANCHOR_HOUR = 20`，报告日期默认取昨天。

| 推送时刻 | 报告日期 | 窗口（东八区） |
|---|---|---|
| 9-2 早上 10:00 | 9-1 | 8-31 20:00 → 9-1 20:00 |
| 9-2 下午 15:00 | 9-1 | 同上 |
| 9-2 晚上 21:00（已过 20 点） | 9-1 | 同上 |
| 9-3 凌晨 00:30 | 9-2 | 9-1 20:00 → 9-2 20:00 |

要点：**同一自然日内不论几点推，内容都一样**；过了午夜 0 点才翻到下一天。
9-1 晚 18:00 抓的那批落在「8-31 20:00 → 9-1 20:00」内，正是 9-2 推送的内容。

## 实现方式（两种写法，选后者）

需求是「今天推昨天那段」。有两种等价实现：

1. 改 `daily_range(day)` 本身，返回 `[day-2 20:00, day-1 20:00)`。
2. 保持 `daily_range(day)` 语义不变（仍是「day 那天的窗口」），
   改 `_report_date()`，未指定 `--date` 时返回**昨天**。

**选 2。** 理由：`daily_range(day)` 保持「day 那天的窗口」这个直观语义，
`--date 2026-09-01` 就是 9-1 的窗口，补推时不用在脑子里做减法；改动面也更小
（只动 `_report_date` 一个函数，`daily_range` 完全不碰）。选 1 会让
`--date` 的含义变成「往前数两天」，补推时极易算错。

### 2. 报告日期默认取昨天（contributors/main.py）

`_report_date(cfg)` 现在的行为：未指定 `--date` 时返回 `None`，
由 `daily_range` 取**今天**。改为返回**昨天**（东八区）。

```python
def _report_date(cfg):
    """--date 指定的日报日期；未指定时取昨天（东八区）。

    取昨天而非今天：锚点在 20:00，今天的窗口要到今晚 20:00 才关闭，
    早上推会推到一个尚未闭合、且必然为空的区间 —— 昨晚 18:00 抓的那批
    落在昨天的窗口里。取昨天后，同一自然日内任意时刻推送内容都一致，
    过了午夜 0 点才翻到下一天。
    """
    raw = getattr(cfg, "date", None)
    if not raw:
        return (datetime.now(timezone.utc).astimezone(period.CST).date()
                - timedelta(days=1))
    return datetime.strptime(raw, "%Y-%m-%d").date()
```

注意事项：
- 用东八区的「今天」再减一天，不能用 UTC 日期减一天（UTC 早上 8 点前
  与东八区差一天）。`period.CST` 已有，直接复用。
- 需确认 `main.py` 顶部已 import `timedelta` 与 `timezone`；缺则补。
- `--date` 显式指定时行为**不变**，仍是「补推那一天的报」。

## 切换时序（关键，别弄错顺序）

| 时刻 | 动作 | 说明 |
|---|---|---|
| 8-31 今晚 18:00 前 | 手动跑 `--fetch` | 入库时刻落在 8-31 20:00 之前 |
| 9-1 早上 **11:00 前** | 正常推送（锚点仍是 11） | 窗口 `[8-31 11:00, 9-1 11:00)`，含昨晚那批 ✓ |
| 9-1 白天（推送之后） | **执行本方案的全部改动** | |
| 9-1 晚 18:00 前 | 抓取（手动或调度） | 落在 `[8-31 20:00, 9-1 20:00)` 内 |
| 9-2 起 | 每天 18:00 抓取、次日任意时刻推送 | 进入稳定循环 |

### 为什么必须按这个顺序

- **今天（8-31）不能改**：今早 10:54 抓的 224 条已经推送过。若现在改锚点，
  它们会落进 `[8-30 20:00, 8-31 20:00)`，明早推送时重复发一次。
- **9-1 推送必须在 11:00 前**：那时锚点还是 11，窗口 `[8-31 11:00, 9-1 11:00)`。
  若拖到 11:30 才推，窗口变成 `[9-1 11:00, 9-2 11:00)`，今晚 18:00 那批
  落在左边界之外，推出来是空的。
- **今晚抓取要在 20:00 之前跑完**：若拖到 20:00 之后入库，它会同时落进
  9-1 早上那次推送的窗口和改完锚点后 9-2 的窗口 `[8-31 20:00, 9-1 20:00)`，
  被推两次。18:00 起跑有 2 小时余量，正常不会踩到。
- **改动要在 9-1 推送之后、当晚 18:00 抓取之前完成**：这样
  `[9-1 11:00, 9-1 20:00)` 这段空档里不会有任何抓取动作，空档虽存在但是空的，
  不造成遗漏。

### 切换后的覆盖检查

- 今晚（8-31 18:00）那批 → 进 9-1 早上的推送 ✓
- 明晚（9-1 18:00）那批 → 进 9-2 的推送（窗口 `[8-31 20:00, 9-1 20:00)`）✓
- 无重复、无遗漏。

## 别忘了改调度

代码改完后，机器人/定时任务的抓取时刻要从 **07:00 改到 18:00**，
推送时刻从 11:03 改到 10:03（或任意白天时刻）。这部分在项目代码之外，
由老板自行调整；README 与 bat 里的 `schtasks` 示例同步改掉，
避免下次有人照抄旧时刻。
