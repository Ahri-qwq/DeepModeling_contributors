# 日报、周报、月报的摘要重试（2026-11-23）

本次修改基于生产版本 `f98099a`，处理模型摘要短暂不可用时过早发送统计卡片的问题。

## 定时行为

所有时间均为北京时间，沿用生产原来的分钟数，第二轮延后一小时。

| 报告 | 第一轮 | 第二轮 |
| --- | --- | --- |
| 日报 | 每天 10:01 | 每天 11:01 |
| 周报 | 周一 10:06 | 周一 11:06 |
| 月报 | 每月 1 日 10:11 | 每月 1 日 11:11 |

选题、定稿分别最多尝试 3 次；一次成功就停止该步骤。两次等待分别为 15、30 秒；服务端要求更长的 Retry-After 时按它等待。每次请求仍有连接 10 秒、读取 60 秒的超时，但不再用 90/150 秒总预算截断重试。内容校验不通过也计入这 3 次。周月报的每个选题批次独立计数。

第一轮摘要不可用时先不发卡片。第二轮继续未成功的模型步骤，再给该步骤 3 次机会；已经成功的选题批次、定稿输出直接复用。第一轮之前准备好的模型证据会保存，避免第二轮换批次、重复选题。模型已正常返回空结果时属于有效结果，不因“无重要内容”再重试。

第二轮仍不可用则发统计卡片；卡片不写“失败”“摘要暂未生成”等模型故障文案，过程日志仍如实记录异常。原有数据覆盖范围提醒保留。

## 发送与恢复

用户选择优先避免重发。定时报告发送前先持久化 `send_started`，随后只调用一次 webhook。之后即使网络超时、响应异常或进程退出，也不会自动再次发送同一期卡片。返回成功时另记 `sent`，因此日志不会把不确定的送达结果冒充成功。

检查点位于 `data/report-delivery/<daily|weekly|monthly>-YYYY-MM-DD.json`；其中保存证据、模型结果、每轮尝试次数和发送标记，不保存 API key 或 webhook。文件原子替换并 fsync。任务通过每种报告独立的 flock 防止重叠执行，日报耗时增加不会阻塞周报。

第二轮由 `REPORT_ROUND=2 ./daily_report.sh --push/--weekly/--monthly` 启动；没有第一轮检查点、已经执行过发送或确认无需发送时自动跳过。不要删除发送标记后重跑，否则会解除去重保护。直接调用 Python 的手动调试入口未设置 REPORT_ROUND 时沿用手动行为；生产和补跑应使用 shell 入口。

## 日志与验证

日志在 `logs/daily-YYYY-MM-DD.log`。记录时间、报告标识、轮次、模型步骤、尝试次数、异常类型/HTTP 状态、耗时、等待秒数、复用结果、延后发送、统计兜底以及发送开始/结果。不输出模型密钥或完整响应。

新增 `tests/test_delivery_retry.py` 覆盖两轮六次、轮内重启不增加预算、成功选题复用、证据冻结、日报/周报/月报首轮延后与第二轮统计卡片、发送超时后不重发。其余报告测试更新为新重试和卡片行为。

生产部署不补发历史日报，也不向群发测试卡片。部署时备份原代码和 crontab，保留其他任务；仅新增三条第二轮任务。
