# 快速开始（供 Agent 与命令行调用）

本文件是**调用手册**：怎么跑、传什么参数、怎么判断成功。
不讲实现原理，那些在 [`../README.md`](../README.md)。

项目根目录（下文记作 `<ROOT>`）：`C:\MyCode\tools\github_contributors`

---

## 一、最常用的四条命令

在 `<ROOT>` 下执行。**bat 必须用绝对路径**，相对路径在部分 shell 下找不到。

```bat
C:\MyCode\tools\github_contributors\daily_report.bat --fetch
C:\MyCode\tools\github_contributors\daily_report.bat --push
C:\MyCode\tools\github_contributors\daily_report.bat --weekly
C:\MyCode\tools\github_contributors\daily_report.bat --monthly
```

| 命令 | 做什么 | 耗时 | 会往飞书群发消息吗 |
|---|---|---|---|
| `--fetch` | 抓取全部仓库、更新表格与事件库 | 约 25 分钟 | 不会 |
| `--push` | 算增量并推送日报 | 数秒 | **会** |
| `--weekly` | 推送上周汇总 | 数秒 | **会** |
| `--monthly` | 推送上月汇总 | 数秒 | **会** |
| `--daily` | 抓取，成功后自动推送 | 约 25 分钟 | **会** |
| `--dry` | 抓取并渲染卡片，只打印不发送 | 约 25 分钟 | 不会 |

**第一次调用请先用 `--dry`**，它不会产生任何外部副作用。

## 二、判断成功与失败

看**退出码**，不要靠解析输出文字（文案会变）。

| 退出码 | 含义 | 该怎么办 |
|---|---|---|
| `0` | 成功 | 无需处理。注意"无新增所以跳过推送"也算成功 |
| `1` | 抓取失败（网络、GitHub 不可用） | 看日志末尾的报错；稍后重试 |
| `2` | 参数错误，或本地缓存缺失 | 检查参数拼写；`--no-fetch` 需先建过缓存 |

日志固定写在 `<ROOT>\logs\daily-<YYYY-MM-DD>.log`，追加模式，每次运行
带 `start` / `done` 时间戳。排障先看这个文件的末尾。

在 PowerShell 里取退出码：

```powershell
& C:\MyCode\tools\github_contributors\daily_report.bat --push
if ($LASTEXITCODE -ne 0) { Write-Error "失败，码 $LASTEXITCODE" }
```

在 cmd 里：

```bat
call C:\MyCode\tools\github_contributors\daily_report.bat --push
if errorlevel 1 echo 失败
```

## 三、不经过 bat，直接调 Python

bat 只是封装。等价的 Python 调用（在 `<ROOT>` 下执行）：

```bat
py -3.12 -m contributors --daily --no-notify          :: = --fetch
py -3.12 -m contributors --daily --only-notify --notify  :: = --push
py -3.12 -m contributors --weekly --notify            :: = --weekly
py -3.12 -m contributors --monthly --notify           :: = --monthly
```

**解释器必须是 `py -3.12`**。系统默认的 `python` 是 3.14，没装依赖，会直接报错。

若输出中文乱码，先设两个环境变量（bat 里已经设好）：

```bat
set PYTHONIOENCODING=utf-8
set PYTHONUTF8=1
```

## 四、参数速查

只列常用的。完整列表见 `py -3.12 -m contributors --help` 或 README 的参数表。

### 控制发不发消息

| 参数 | 作用 |
|---|---|
| `--notify` | 推送到飞书群。**不加就不发** |
| `--notify-dry-run` | 渲染卡片打到 stdout，不发送。调试首选 |
| `--notify-empty` | 无内容时也发。平时不需要 |
| `--no-notify` | 跑统计与入库但不推送 |
| `--only-notify` | 只算增量并推送，跳过采集（秒级） |

### 控制跑哪些仓库、写哪里

| 参数 | 默认 | 作用 |
|---|---|---|
| `--daily` | 关 | 只维护两张总表，输出到 `output/daily` |
| `--repos A,B` | 全部 | 只跑指定仓库，逗号分隔 |
| `--out-dir` | 见左 | 输出目录。全量默认 `output/all` |
| `--no-fetch` | 关 | 零网络，纯本地缓存重算 |

### 周期汇总

| 参数 | 作用 |
|---|---|
| `--weekly` | 上周一至上周日的汇总 |
| `--monthly` | 上月整月的汇总 |

两者只读事件库，秒级完成，不跑采集。

## 五、四个典型场景

**只想看看会发什么，不发送**

```bat
py -3.12 -m contributors --daily --only-notify --notify-dry-run
```

秒级完成，打印完整卡片 JSON。

**手动补发今天的日报**

```bat
C:\MyCode\tools\github_contributors\daily_report.bat --push
```

**只跑一两个仓库快速验证**

```bat
py -3.12 -m contributors --daily --repos deepmd-kit --notify-dry-run
```

**重发上一次的卡片（调通道用）**

```bat
py -3.12 -m contributors --resend-last --notify
```

不重算增量，直接把存档发出去。

## 六、五个必须知道的坑

**一、往 `--repos` 里加新仓库后，先跑一次 `--mark-notified`。**

事件库按"首次看到"判定增量，新仓库的一整年历史会被当成昨天的动态推出去。

```bat
py -3.12 -m contributors --daily --mark-notified
```

**二、`--fetch` 要 25 分钟，别用短超时包它。**

耗时受当天新提交量与网络影响，实测 24～28 分钟。`--push` 才是秒级的。

**三、bat 必须用绝对路径。**

相对路径 `daily_report.bat` 在 Git Bash 等 shell 下会报"不是内部或外部命令"。

**三之二、注意你在哪个 shell 里。**

Windows 上同时存在 PowerShell 与 Git Bash，语法不通用，混用会静默失败：

| 操作 | PowerShell | Git Bash / cmd |
|---|---|---|
| 设环境变量 | `$env:PYTHONUTF8='1'` | `export PYTHONUTF8=1` |
| 丢弃输出 | `\| Out-Null` | `>/dev/null` |
| 取退出码 | `$LASTEXITCODE` | `$?` |
| 调 bat | `& C:\...\daily_report.bat --push` | `cmd //c "C:\\...\\daily_report.bat --push"` |

在 PowerShell 里写 `>/dev/null` 会创建一个名为 `C:\dev\null` 的文件并报错。

**四、只能以当前 Windows 用户身份运行。**

GitHub token 来自 `gh` 的凭据管理器，换用户取不到，会以鉴权错误失败。

**五、"跳过推送"不是失败。**

无新增内容时会打印"跳过推送"并返回 0。这是正常行为，不要当错误重试。

## 七、需要什么前置条件

| 条件 | 检查命令 | 缺了会怎样 |
|---|---|---|
| Python 3.12 | `py -3.12 --version` | 报错退出 |
| 依赖已装 | `py -3.12 -c "import requests"` | ImportError |
| GitHub token | `gh auth status` | 鉴权失败，退出码非 0 |
| 飞书 webhook | 看 `<ROOT>\.env` 是否存在 | 推送失败，但统计不受影响 |

`.env` 需含：

```
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx
FEISHU_WEBHOOK_SECRET=
```

## 八、产出在哪

| 路径 | 内容 |
|---|---|
| `output\daily\summary.csv` | 跨仓库汇总，一人一行 |
| `output\daily\by_repo.csv` | 一人一仓库一行 |
| `output\all\` | 全量模式的完整产出（含附表） |
| `data\events.db` | 事件库（SQLite），增量判定的依据 |
| `logs\daily-<日期>.log` | 运行日志 |

`data\events.db` 不要随意删除：里面"第几次运行首次看到"这个信息重建不了，
删了会导致下一次推送把全部历史当成增量。
