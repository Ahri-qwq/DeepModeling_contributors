# 卡片语义化运维日志

日期：2026-09-18
状态：第一步（规则分类）已上线
相关：`contributors/notify/classify.py`、`card.py`、`period.py`

## 一、为什么做这件事

日报原本是**事件流**：25 个 PR、12 个 issue、38 个仓库在动。运营看完知道"很热闹"，
但答不出任何一个真正的问题——deepmd-kit 最近是在修 bug 还是推新功能？上个月那个
大重构做完了吗？社区最近集中在抱怨什么？

原因是数据停在**动作层**（谁在什么时候动了什么），没有到**意图层**（他们在解决
什么问题）。这份日志记录把它往意图层推的过程。

## 二、这次改了什么

| 项 | 改动 | 理由 |
|---|---|---|
| 日报分区 | 按 PR 状态改为按意图 | 运营要的是"在干什么"，不是 PR 生命周期状态 |
| 日报条数 | 每类最多 5 条 | 原来每类 10 条卡片太长；实测日均 11 个 PR，5 条够用 |
| PR 状态 | 移到条目行首 `[合并]` / `[新建]` | 分区名不再承载这个信息，不标就丢了 |
| 周月报 | 新增「PR 动向」分区 | 仓库 × 意图矩阵，回答"这些仓库在干什么" |
| 分类来源 | 只用 PR | commit/issue 的前缀规范度太低，见下表 |

### 为什么只分类 PR

实测近 90 天的 conventional commits 前缀覆盖率：

| 类型 | 覆盖率 | 是否参与分类 |
|---|---|---|
| PR | 75% | 是 |
| commit | 44% | 否 |
| issue | 9% | 否 |

除了覆盖率，还有个更本质的理由：commit 是**过程**不是**意图**。一个 PR 里混着
大量 "fix typo"、"address review"，按 commit 分类会让改错别字和重写求解器占同样
的权重。

### 分隔符的权衡

分类器不只认 `fix:` 这种规范写法，也认空格和斜杠分隔（`Fix module_hs`、
`perf/Optimize neighbor-list`）。只认冒号的话，近 90 天有 100 个明确可判的 PR 会
掉进「其他」——识别率会从 75% 降到 65%。

代价是理论上可能误判 `Fix` 开头的自然句，实测样本里没有这种情况。

## 四、后续 todo

按优先级排。**注意区分哪些需要 LLM、哪些不需要**——这点容易搞混。

### 1. 画像句（不需要 LLM）

在周月报的仓库行后面加一句话总结，比如「以修复为主」「大规模重构进行中」。

纯规则即可：按类别配比套模板（修复占比 > 50% 就说"以修复为主"）。**不需要 LLM，
也不需要给这个项目配 LLM。**

卡住的是话术口径——这些话运营会拿去汇报，措辞要用户自己定。

### 2. 「其他」类语义分类（需要 LLM）

把那 25% 认不出的 PR 用 LLM 打标签。这是**真正需要 LLM 的第一件事**。

设计要点：
- 走**离线批处理**，不是实时。crontab 抓数据时顺便跑一次，结果写回数据库
- 和六小瓜的在线状态解耦——六小瓜挂了日报照发
- 只处理正则认不出的，75% 已识别的不重复消耗
- 出错要有记录可查（日报无人值守，错了没人发现）

成本可控：每天 25% × 十几个 PR，量很小。

### 3. 六小瓜飞书群内问答（需要 LLM，依赖 2）

在飞书群 @ 六小瓜追问细节：

```
@六小瓜 这条 PR 是啥意思？
@六小瓜 abacus 最近在干嘛？
@六小瓜 这周有什么能写推文的？
```

链路是通的——六小瓜飞书侧已有 `push_github_daily_report` 等 LLM 工具，说明工具
注册和群内响应都跑得起来。要加的是几个查询工具，让她能读 `data/events.db`
（17758 条事件）。

**设计红线**：必须基于数据库真实记录回答，查不到就说查不到。社区信息被编错了比
没有更糟——运营拿去对外说就出事了。

### 4. 人的维度（不需要 LLM）

现在完全没做，但可能是最能驱动运营行动的：

- 新面孔（首次贡献者）
- 活跃度突变（某人突然连提五个 PR）

`author_login` 字段一直都在，`event_state_changes` 还能看状态流转。纯 SQL 能做。

看板现在只能按仓库/时间筛，加一个按类型筛选就能回答"abacus 这三个月的重构占比
在上升吗"。分类字段已经有了，这是小增量。

## 六、口径提醒

周月报里「活跃仓库」和「PR 动向」是**两个不同口径**，同一个仓库在两边的数字和
排名都可能不一样：

- 活跃仓库：全部事件（commit + PR + issue），措辞「N 次活动」
- PR 动向：只数 PR，措辞「N 个 PR」

实测上周 dpgen 活跃度第一（56 次活动，大部分是 commit），但 PR 动向里 abacus
第一（32 个 PR）。这不是 bug。措辞上刻意区分，且 PR 动向不写序号，避免读成排名打架。
