### 修过的四个缺陷（不要改回去）

一、时间窗过滤（`1277d64`）。`git log --since/--until` 过滤的是
committer date，而本项目口径是 author date，两者在 rebase/squash 场景可
相差数月。且 `--since` 会截断遍历：分支顶端若有旧日期提交，其祖先中窗口
内的提交会被整片漏掉。现改为 git 侧取全量、Python 侧按 author date 筛。
git 没有按 author date 过滤的选项，`--since-as-filter` 也是 committer
date 口径。

二、`--no-fetch` 联网崩溃（`b38f764`）。该模式声称零网络，但仍调用
`fetch_repos` 拉仓库清单，而该模式不取 token，空 token 请求返回 401 直接
崩溃。现把清单纳入缓存。注意：原集成测试 monkeypatch 掉了 `fetch_repos`，
恰好绕过会崩的路径而掩盖了问题 —— 这类 patch 要警惕。

三、身份被拆成两行（`b38f764`）。未在 GitHub 登记的邮箱查不到 login，
同一人被拆开。实测 Han Wang 拆成 1151+110、dyzheng 拆成 128+278，榜首
根本没显示出来。现有 `merge_by_name` 在同仓库内按姓名合并，规则保守：
姓名完全相同、且只对应一个 login 才合并。

四、fork 上游排除失效（`a0f6a99`）。`build_rows` 原用
`upstream_counts.get(email, gs.commits)` 兜底，但
`count_upstream_excluded` 只列出上游不可达的人。某人提交全来自上游时他
不在字典里，兜底反而把 `not_in_upstream` 抬成 `commits`，与设计意图相反。
实测 GPUMD 的上游作者 Zheyong Fan 显示 207/207，实际应为 207/0。现改为
fork 缺失即记 0，非 fork 才等于 commits。同时用 `None` 区分「上游对比
失败，无从判断」与「对比成功但无人独立于上游」，前者退化为 commits。

## 八、几个容易踩的坑

Windows 环境。终端输出中文会显示为乱码，但文件内容正常，加
`PYTHONIOENCODING=utf-8` 可缓解。`git log` 的字段分隔符不能用 `\x00`
（CreateProcess 不允许参数含 NUL），项目用的是 `\x1f`。删除 git 缓存
目录不能用 `shutil.rmtree(ignore_errors=True)`，pack 文件带只读位会
残留空壳目录，项目用 `onexc` 回调清只读位。

Excel 占用文件会让写 CSV 报 PermissionError。若遇到，让用户关掉窗口，
或临时输出到别的目录。

`--no-fetch` 跳过 GitHub API，PR/issue 列全为 0 且 email→login 映射
缺失（实测 236 人掉到 175 人，仅 41 人能关联账号）。它只适合验证 commit
口径，出正式名单必须走完整跑法。

权限分类器偶尔不可用，报「temporarily unavailable」。等一下重试即可，
不是代码问题。
