## 四、需要你重点检查的五件事

### 1. 榜首是 CI 机器人，不是人

未筛选的 summary.csv 第一行是 `github-actions[bot]`，2931 次提交，其中 2929 次来自
`.github` 仓库 —— 那是组织的配置仓库，提交全部由 CI 自动产生。它按你的口径保留在
名单里并标注 `is_bot=True`，公示前需要处理掉。

被标注的 10 个 bot 账号：

| 账号 | 提交数 |
|---|---|
| github-actions[bot] | 2931 |
| njzjz-bot | 567 |
| pre-commit-ci[bot] | 461 |
| dependabot[bot] | 292 |
| njzjz-bot（另一邮箱，无账号） | 219 |
| coderabbitai[bot] | 2 |
| codecov / dependabot / github-actions / pre-commit-ci | 0（仅有 issue 评论或 PR） |

在 Excel 里按 `is_bot` 列筛 True 即可一次性看到或删掉。

### 2. 四个 AI 账号

| 账号 | 提交 | 评审 |
|---|---|---|
| Copilot | 355 | 0 |
| copilot-pull-request-reviewer | 0 | 416 |
| claude | 2 | 0 |

`copilot-pull-request-reviewer` 有 416 次 PR 评审，数量不小。按 `is_ai_assistant`
列筛 True 可看到全部四个。

### 3. abacus_fixer 仍是名单第二位

750 次提交，邮箱 `mohanchen@pku.eud.cn`（edu 拼成 eud，故查不到账号）。
你说这个问题先搁置，所以它作为独立条目留在名单里，未与 mohanchen 合并。
如果最终确认是同一人，mohanchen 的实际提交数会显著上升，名单排序也会变。
这是本次名单里影响最大的单个不确定项。

### 4. njzjz-bot 被拆成两行

`njzjz-bot`（567 次）与 `njzjz.bot@gmail.com`（219 次，无账号）是同一个机器人的两个
邮箱，后者未在 GitHub 登记所以查不到账号。姓名完全相同但两条都缺 login 时自动规则
不敢合并 —— 这是刻意的保守设计，宁可漏合并也不错合并。若确认，实际是 786 次。

unmatched.csv 里还有类似情况，需要人工过一遍。

### 5. sciencepedia 只有 1 人，数字是对的但不可比

窗口内只有 xiaoyan（`xiaoyan@dp.tech`，无 GitHub 账号）的 25 次提交，
最后一次是 2026-02-10，之后仓库没有动过。全历史有 289 次提交、10 位作者，
但都在窗口之前。

已核实这不是统计错误。但要提醒：这 25 次提交的 message 都是
`Sync wiki data batch: keyword_id_keyword_...`，是批量同步知识库数据，一次可能写入
上千个词条文件。它与「25 次代码提交」的工作量完全不可比，是否计入表彰、如何折算，
建议单独讨论，不要直接并进主名单排序。

## 五、其余不确定的地方

### AI 指派人只追溯到约一半

390 次 AI 助手提交中 186 次能从 `Co-authored-by` 追溯到指派人，覆盖率 48%。
追溯到的：njzjz 122 次、link89 24 次、anyangml 12 次、HydrogenSulfate 9 次、
Cstandardlib 7 次，明细见 ai_assisted.csv。

剩余 204 次提交信息里没有任何指派人线索，无从追溯。所以这张表只能当线索用，
不能当作 AI 提交的完整归属。两个数字都记在 run_meta.json 的 `ai_commits_traced`
与 `ai_commits_untraced`。

guess 列本次全部为空 —— 说明名单中没有同名的已知账号可作线索。

### 34 个被跳过的仓库

19 个最后推送早于 2026-01-01（工具连克隆都不执行）；7 个是 external 或 tooling 类
fork，按你确认的口径排除，包括 GPUMD、lammps、plumed2、fealpy、msys 等；
sciencepedia 走单独一趟；其余为 argo-workflows、get-changed-files 这类 CI 工具 fork。
完整清单见 run_meta.json 的 `skipped` 字段，每条都带跳过原因。

如果将来把统计区间往前挪到一年以上，会有更多沉寂的 fork 进入流程，而它们的
`upstream_family` 分类未经人工确认。README 顶部已就此加了醒目提示。
